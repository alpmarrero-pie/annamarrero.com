AI Model Design

Analysis Agent

From 7.5 days to 2 hours, without losing trust

Competitive analysis is one of the credit union’s most-used research inputs, and one of the most manual. I proved an agent could do it, then tested how it fails.

Challenge

With little room to test, the credit union watches competitors. Every site is checked by hand. One pass can take weeks.

My role

I’d run these analyses for years. I proposed automating them, wrote the prompt, built it with IT, and ran three rounds of testing.

01 · Use case

Prove it before building it.

I gave Co-Pilot analyses I’d already done and compared its answers to mine. They held up. Then I pulled past analyses from across the org to find the common competitors, features and formats. That became the first draft.

Manual

  1. 1Open every competitor site
  2. 2Search for the topic
  3. 3Log whether it exists
  4. 4Note how it’s marketed
  5. 5Compile and recommend

One pass can take weeks.

With the agent

  1. 1Fixed control prompt
  2. 2Agent reviews each site
  3. 3Scored, sourced table
  4. 4Human review and re-prompt

About two hours. A person checks the evidence.

What I’d do differently

Mistake 1 · No accuracy baseline

I judged accuracy by eye. A scored baseline would have given every round a number to beat.

Mistake 2 · Prescribing instead of asking

I told the model exactly what to report. Sharing the goal and asking for a plan would have surfaced better ideas.

02 · Testing

Testing that fits around real work.

Testing was async. A pre-survey captured time, confidence and ease of use. Everyone started from the same prompt, so results compared cleanly.

03 · Failure taxonomy

Know how it fails.

Speed only matters if people trust the output. I logged every error and grouped them into six patterns, each with a fix.

Six patterns · one example each

  1. AUnable to read visual content

    Said a page had “zero photos, icons, or visual illustrations” when it had both.

  2. BSkips sub-navigation

    Accessed a landing page but skipped the sub-navs linked on it.

  3. BBlames imaginary restrictions

    Said it was “unable to access” a credit card page, though it had accessed the page beside it.

  4. BOverconfident

    Tagged inferred findings as direct evidence.

  5. BSearches first

    Relied on search and said a page didn’t exist when it was in the main nav.

  6. CInconsistent formatting

    Table structure and content changed from one response to the next.

Three fixes

AAsk for the visual

For visual tasks, ask for a screenshot. Don’t guess.

BMake evidence traceable

Source every claim. Tag evidence and confidence. Cap weak scores. Follow the site’s own structure.

CLock the format

Same format every time, unless asked.

Scoring rule

Scores built on secondary or inferred evidence are capped at 3 and flagged for review. Every score explains why it isn’t higher, and why it isn’t lower.

04 · Next

Clear limits build trust.

Speed alone won’t drive adoption. Next: define what the agent can’t do, and when a person must step in.

  1. 01Survey people on analysis with and without the agent.
  2. 02Reprogram the agent for each failure pattern.
  3. 03Measure against the taxonomy to define its limits.
  4. 04Share templates and guidance: what it does, when it needs a human, how to keep it transparent.
